# decl/: the declarations of what the port of Simplify calls

Every `.v` file here is GENERATED by `tools/declgen` from the compiled
interfaces of the compiler. Do not edit one: change the generator and run it
again. `INDEX.tsv` and `NOT-DECLARED.tsv` are generated with them.

One file for each compilation unit of OCaml that the 78 files of
`middle_end/flambda2/simplify/` use, named as the unit (`Downwards_acc.v`,
`Flambda.v`, `List.v`), and one for each file of Simplify itself (whole
interface). A sub-module of OCaml is a `Module` of the file. Each file begins
with the header of the interface that it follows, then names it and the commit.

## To make them again

    cd middle_end/flambda2/rocq/simplify_port
    tools/declgen/run.sh BUILD_ROOT          # every file of Simplify
    python3 tools/declgen/compile_all.py     # Rocq, one process at a time
    python3 tools/declgen/check_realisations.py BUILD_ROOT   # OCaml

What the last one checks, and what it does not. For each realisation string
it writes one line of OCaml (the string as an expression; for a type, as the
type of an argument; for a constructor or a field of a mirrored type, a
pattern or a projection with its name), and OCaml type-checks the lines
against the compiled interfaces, with `-nolabels` and the libraries that the
build opens for Simplify. So a name that does not exist, a wrong number of
type parameters, or a closed function that does not type is refused. For a
tuple with labels it also checks that the two functions of the directive make
and take the type that the directive names. It does
NOT compare the type that OCaml gives a realisation with the signature that
the declaration has in Rocq: that is checked only where a ported file uses
the declaration, by the check of the extracted file. Left out, and counted
apart in what it prints: the constructor functions of private types (OCaml
makes no value of such a type outside its module; the port must not build
one); what is declared of a module local to a file (`FILE__local.v`) when
that module is inside another module of its file, or when its definition,
copied from the file, does not compile apart from it.

`BUILD_ROOT` is the `_build/default` of a dune build of the compiler at the
commit of the sources (its `.cmt` and `.cmi` files are read; nothing is
written there). The generator is OCaml and is compiled against the
`compiler-libs` of the OCaml that made that build (`ocamlfind` in the path).
The same inputs give the same bytes.

## What is read, and how a thing is found

The typed trees (`.cmt`) of the 78 files say what each uses: every value,
every constructor built or matched, every field, every type written, every
exception, each resolved by the compiler's own environment. A file that
gives a module to a functor of its own (`Edge (Name.Map) (Name.Set)` in
`flow/data_flow_graph.ml`) uses, of that module, what the body of the functor
uses of its parameter (`Src_map.find` is `Name.Map.find`); the modules of the
file are followed for that, through a structure written in the place and
through the result of another functor of the file. An abbreviation of
a module in a file of Simplify (`module DA = Downwards_acc`,
`Simplify_import.T`) is followed; a module that another interface makes an
alias (`Code_id.Map`, which is `Int_ids.Code_id.Map`) keeps the name that the
sources write, and its items are declared again under that name, its types
defined as the types of the module that it names. Then the interface (`.cmi`)
of each unit is walked in its own order, and what is used is declared, with
every type that a declared thing mentions (to a fixed point). `INDEX.tsv`:
OCaml name, Rocq name, kind, number of arguments, interface and line.

## The form (GUIDE.md has the rules; this is what the generator does)

- A function: `Parameter f : a -> b -> M c.` Arguments by place in the order
  of the interface; labels are dropped; every arrow, at any depth, has its
  result in `M` (so a callback is `a -> M b`), unless the result is an
  abbreviation of a function type (`... -> Simplify_common.rebuild a`): the
  `M` is then at the end of that one. Realised by its plain name.
- An optional argument: by place, of type `option a`; the realisation is a
  closed function that passes it with `?l:`.
- A function with a format (`Format.fprintf`): one declaration for each number
  of arguments after the format, `fprintf0` to `fprintf16`, the format a
  `string`, all realised by the same name.
- A value that is not a function: pure, `Parameter empty : t.`
- An exception: `Parameter E : exception payload.`, realised by a pair (the
  maker, the test).
- A type that Simplify does not take apart: `Parameter t : Type.` With no
  parameter it has `Extract Inlined Constant t => "Mod.t"`: Rocq prints the
  string wherever the type is used. With parameters it has
  `Extract Constant t "'a1" => "('a1) Mod.t"` (Rocq has no inlined directive
  for a type with parameters): the string is for the type's definition, which
  is never printed since no file of decl/ is extracted; where the type is
  used, in a term or a comment, Rocq prints its name in Rocq, which is the
  compiler's when the modules have the compiler's names.
- An abbreviation: a `Definition`. So is a variant or a record that an
  interface gives again from another unit (`Coercion.t`, which is
  `Int_ids.Coercion.t`, also when its constructors are private): the two are
  one type in Rocq as in OCaml. A private abbreviation (`type t = private
  int`) stays abstract: it is not equal to its definition.
- A variant that Simplify builds or matches: an `Inductive` with the
  compiler's constructors, and always an `Extract Inductive` that gives each
  constructor its qualified name in OCaml (so a constructor that had to take
  a `_` in Rocq is still printed right): Rocq prints `Mod.C (a, b)` in terms
  and in patterns. A constructor with an inline record takes the fields by
  place, in the order of the type; its string is a function of the tuple of
  its arguments, and the directive then has a third string, the match (one
  function for each constructor, then the scrutinee): a `match` of Rocq on
  such a type is printed as that function applied to one function for each
  branch. The same form, with the type written in the strings, for a variant
  one of whose constructors has the name of a constructor of a later type of
  its module (OCaml would take the bare name for the later type). No field of
  an inline record is a name of Rocq. `INDEX.tsv` gives the place of each
  field (`inline field`).
- A record whose fields Simplify reads or builds: a `Record` with the
  compiler's fields; a mutable field also has `set_FIELD`.
- A tuple with labels (`a * annotations:b * c`): a type of its own with one
  constructor, an `Inductive` with an `Extract Inductive`. Rocq has no label
  in a tuple, and OCaml refuses the tuple without its labels. The type's
  string is the tuple type of OCaml; the constructor's string is a function
  that makes the tuple with its labels from a plain tuple; the third string
  takes it apart, so a `match` of Rocq on it is printed as that function
  applied to the branch. One type for each such tuple type, declared in the
  module whose interface writes it first, before the item that writes it, and
  used wherever the interfaces write that tuple type. Its name is that of the
  labelled argument or of the field where it is first written, or else its
  own labels, then `_tuple`; its constructor has the same name with a
  capital: `Simplified_expr.arms_tuple` and `Arms_tuple`,
  `Upwards_env.handler_tuple`, `Downwards_env.forwarded_from_tuple`.
- Types defined together (`type a = ... and b = ...`): the abstract ones
  first, then the others, each after what it mentions; variants that mention
  each other are one `Inductive ... with ...`.
- A type that cannot be so (a GADT; a type that holds itself inside an
  abstract type; a record recursive with other types; a record with a field
  name already taken, or in a module inside a file whose name Rocq reserves):
  abstract, marked `PORT-GAP(type)`, with a pure maker `mk_C` for each
  constructor and one eliminator `match_T` whose branches are in `M`. (No
  maker for a private type: OCaml makes none outside its module. No
  eliminator for a GADT.)
- A module that a file of Simplify names by an alias exists, though empty.
- Every file ends with an empty module of its own name (`Module Simple. End
  Simple.` in `Simple.v`), which the interface does not have. It is there so
  that Rocq, of itself, writes no `open` of a file of decl/ in what it
  extracts. Without it Rocq's extraction
  writes `open U` in a file that uses a name of `U` that Rocq prints itself (a
  type with parameters, a record, a field, a module), and prints such names
  without `U.`. In OCaml that `open` brings every name of the real module,
  and Rocq knows only what is declared here (and of that, not what is an
  inlined string). So a short name could be a name of another opened module
  in OCaml (`Map.t` after `open Tag`: the compiler's `Tag` has a `Map`), and
  the head of a realisation could be hidden (`List` after `open Simple` is
  `Simple.List`). Rocq writes no `open U` when `U` has, at its top, a module
  with the name of a file in use, and `U` is in use where it would be opened.
  So with that last line Rocq prints each name of a file of decl/ in full
  (`Apply_cont_rewrite_id.Map.t`, `r.Flow_types.Acc.stack`). Only the `open`s
  that Rocq inserts by itself go. `open Port_monad` stays, and so does an
  `open` that a port file carries as OCaml text (such as `open
  Simplify_import`).

## Names

The compiler's, except: a word that Rocq reserves gets one `_` after it
(`Variable_`, `Set_`, `Import_`, `at_`); the unit `Stdlib` is `Stdlib_`. Rocq
has one name space where OCaml has several: a constructor or a field of a
mirrored type always keeps its name (Rocq prints it); a value or a type of the
same name in the module gets `_` (`descr_`), wherever it is declared, and so
does a second declaration of a name. Type variables are capitals (`'a` is
`A`). `INDEX.tsv` has every name.

## What the generator cannot translate, and what it does instead

| OCaml | what is done |
|---|---|
| labels | dropped: arguments by place |
| optional arguments | `option` by place, a closed function as realisation |
| format strings | a family by the number of arguments (0 to 16) |
| operators of `Stdlib` (`&&`, `<>`, `@`) | not declared: the kit and Rocq have their own |
| operators of other modules (`Code_size.(+)`, `let<*`) | a name spelled from the characters: `op_plus`, `let_op_lt_star` |
| functors | not declared. An instance that an interface names (`Variable.Map`) is a module like another |
| a functor of outside applied inside a file of Simplify | the module is declared in `FILE__local.v` (below). Not declared: `Set` and `Pair` inside the functor `Binary_arith_like` of `simplify_binary_primitive.ml`; the `include` of `non_constructed_code.ml` |
| module types | not declared |
| GADTs | abstract, with makers only (no eliminator: its branches could not have one type) |
| polymorphic variants | given as an index to an abstract type or a GADT (``[`Unarized] Flambda_arity.t``): dropped, with the parameter; each instance that the interfaces write is a named abbreviation of the type (`Flambda_arity.t_Unarized`, `t_Complex`), used where the interface has that instance and printed as the instance in OCaml; the bare `t` is where the interface has `'a t` or `_ t`. Elsewhere the declaration is left out |
| first-class modules, objects | the declaration is left out |
| a type with parameters in a module whose name Rocq reserves (`Variable.Map.t`) | it has its `Extract Constant` like another; where it is used Rocq prints `Variable_.Map.t`, so the runtime has `module Variable_ = Variable` |

## Left to write by hand

`NOT-DECLARED.tsv` lists every used thing that has no declaration, with the
reason. The kit (`Port_monad.v`) has `ref`, `!`, `:=`, `raise`, `ignore`,
`compare`, `not`, `Lazy.force`, `Not_found`, the fatal errors: they are not
declared here.

## The modules that a file of Simplify makes for itself

A file of Simplify that applies a functor of another part of the compiler
(`module G = Strongly_connected_components.Make (Continuation)`), or has a
module with such an `include`, has a file `FILE__local.v` here: one `Module`
for each such module, in the usual form, with what the file uses of it. The
realisations name the module as the file does (`G.component`), so the port
keeps the module's definition in the extracted file as it is, and writes
`From SimplifyPort.decl Require Import FILE__local.` A module inside another
module of the file is inside a `Module` of that name
(`Rebuilt_expr__local.Matching_for_unique_handler.Match_permutable_parameters.HV`).
A `FILE__local.v` also ends with an empty module of its own name: it is no
module of OCaml, so an `open` of it could not be right. One thing in these
files is not an inlined string: the type `'a HV.t` of `rebuilt_expr.ml`, which
has a parameter. Where the port uses it Rocq prints its name in Rocq, the path
above with `.t`, which is no name of OCaml until the port of that file gives
it one.

| file of Simplify | modules |
|---|---|
| `common_subexpression_elimination.ml` | `Rhs_kind` (the whole module: its type, `bound_to`, its sets) |
| `flow/control_flow_graph.ml` | `G` |
| `flow/dominator_graph.ml` | `G` |
| `lifting/lifted_constant_state.ml` | `SCC_lifted_constants` |
| `number_adjuncts.ml` | `For_int8s.Num.Pair`, `For_int16s.Num.Pair` |
| `rebuilt_expr.ml` | `Matching_for_unique_handler.Match_permutable_parameters.HV` |
| `simplify_let_cont_expr.ml` | `SCC` |

Not declared: `Set` and `Pair` of `simplify_binary_primitive.ml` (lines 99 and
508), which are made inside a functor of the file and depend on its parameter
(the port of that functor has them); the `include` of
`Code_metadata.Code_metadata_accessors` in `non_constructed_code.ml`, of which
the file itself uses nothing. Module types (9, in `NOT-DECLARED.tsv`) are not
declared.
