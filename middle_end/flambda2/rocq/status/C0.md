## How a merge goes

1. The orchestrator says "merge `<branch>` at `<commit>`, signed off by
   R1". One merge at a time.
2. `git merge --ff-only <commit>`. If it does not fast-forward, say so:
   the owner rebases. There are no merge commits.
3. If the branch ends with a commit `<stream>: lines for the shared
   lists`, check that it touches only the lists of `rocq/Makefile` and
   of `FlambdaExtract.v`, and adds only lines for that stream's files,
   each in its place in the order (`rocq/HACKING.md`, "Adding a
   module").
4. On top, as commits of C0's: the regenerated extracted files, and
   whatever of `rocq/HACKING.md` and of the layout of `OWNERS.md` the
   merge calls for.
5. Validate (below) and report the new tip to the orchestrator.

## Validation

After every merge and every commit of C0's that is not a `.md` file
only:

- `make -C rocq -j16 all`
- `make -C rocq assumptions`
- the semantics tests,
  `@middle_end/flambda2/tests/semantics/runtest`
- `git status` is clean
- `make -s test` as well, if an OCaml or dune file changed. One of its
  tests fails on this branch and is not ours:
  `tests/backend/ssa/loop/bounds_check_elim.ml`.
