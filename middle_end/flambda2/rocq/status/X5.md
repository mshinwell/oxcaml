# X5: the compiler's own run as a second mode of the test tool

## Done

- `middle_end/flambda2/tests/tools/ownrun/flsemantics_ownrun.ml`: the driver of
  the compiler with the hooks `Raw_flambda2` and `Flambda2` registered,
  which gives the two terms of the compiler's own run to
  `Flsemantics.check`. It takes the compiler's command line, prints
  what the tool prints, and exits 1 where the check failed. It is in a
  directory of its own and is built in the main context only, as it
  needs the library `unix`; the modules of the check are copied there.
- `middle_end/flambda2/tests/semantics/ocaml/own_run.sh` and the rules
  (`gen_rules.sh`): a unit that has `X.own_expected` is compiled by the
  driver and what it prints is compared with that file.
- `middle_end/flambda2/tests/semantics/own_run/`: a control of the
  driver given two units in one process, the first in the classic mode.
- `tests/semantics/ocaml/README.md`, "The compiler's own run": what the
  second way differs from the first in, what a verdict of it rests on,
  and what it finds of the 347 units at 87cdbf3e01.

## Measured with the driver of this series

At the default flags, of the 347 units of `tests/semantics/ocaml/` at
87cdbf3e01: 242 print "validated" (22 of them with their imports; one
of the 242 is `empty_array_phys_equal.ml`, whose run is undefined in
the model, so 241 of the 325 that the tables of the README count), 86
not checked (82 at a `Make_block` whose fields have a kind that is not
any value), 16 not validated, 3 whose term after is not well-formed
(the driver exits 1).

## Not in this series

- Expected files (`X.own_expected`) and tables: V2's. None is added
  here, so no generated rule of the own run of an example runs yet;
  the control runs.
- The conversion is the tool's as it is. It refuses a `Make_block`
  whose fields have a subkind or are never null, which the terms in
  memory have and the text has not, so 78 units that the first way
  validates are "not checked" in this one until that is decided (C2's
  proposal; a decision of the human's).

## Open

- `div_unknown.ml`, `string_get16_checked.ml` and
  `string_get_twice.ml`: the compiler's own term after is not
  well-formed (discrepancy X5-9; with the request on statics at
  toplevel). The driver exits 1 on them, so they can have no
  `X.own_expected` until that is decided.
- `string_get_in_branch.ml`, `string_get_two_indices.ml` and
  `string_length_after_join.ml`: validated in the first way and not in
  this one. The compiler keeps the handler of the failed bounds check,
  which is cold, as a handler of its own; the validator does not accept
  the pair.
- The 16 units of `ocaml/pairs/`: `own_run.sh` does not give the driver
  the `.cmx` file of a first unit.
