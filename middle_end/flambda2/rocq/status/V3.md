# V3: lifting to symbols, for the validator

What this file describes is merged, but for what it says is not in
this tree yet. (The roster's V3; not the converter of `OWNERS.md`'s
section V3. The files are listed under S5 there.)

## Aim

Units in which Simplify makes a closure, an immutable block, a boxed
number or an immutable array of values a symbol are validated by
`validate_unit`, not only compared on one run.

## Done

Merged: the law of the primitives and the simulations.

- `FlambdaPrimitiveSpec.eval_prim_related_statement`, a law of the
  primitives, with its proof: for a relation between values under which
  the observations agree (`respects_observations`, in three named
  parts), a primitive that has a value has one on related arguments,
  related to it. Every stream that adds a primitive owes its case in
  `FlambdaPrimitiveProofs.v` (the section "A primitive cannot tell
  related values apart").
- `FlambdaSimulationProofs.v`: a simulation in which each step of the
  first run is answered by one or more of the second gives `refines`
  (`stuttering_refines`); no measure is needed.

This series, behind the epoch of kinds (terms carry kinds; a unit has
an interface, which `lift_unit` takes for the check of
well-formedness):

- `FlambdaLiftSpec.v`:
  - `lift_expr lets at_path e`: each `Let` named by the guess becomes
    `Let_static bindings (Let x = Symbol s in body)`, in place, for
    `Closure_of_set` (the whole set, by `bind_closures`),
    `Set_of_closures`, `Make_block` and `Box_number`. A `Let` is named
    by its path in the term. Code and the handlers of recursive
    continuations are not gone into.
  - `exits_plain scope e`: a variable is given only to continuations
    bound by a `Let_cont` or to the return continuation of code, every
    call returns to one, and the extra arguments that a call has for
    its exception continuation are symbols and constants unless that
    continuation is bound by a `Let_cont` around the call.
  - `lift_unit L e`: the check and the rewrite together; extracted.
  - `value_lifted statics' v v'`: the same value, or a symbol bound to
    it, here and inside closures and blocks.
- `FlambdaLiftProofs.v`, no `Admitted`, no axiom: `lift_simulates`,
  `lift_unit_program_refines`, `exits_plain_sound`,
  `lift_expr_equivariant`, `exits_plain_equivariant`.
- `FlambdaMyClosureSpec.v`: `bind_my_closures known e` puts
  `Let my_closure = Symbol s` at the head of the code of each code id
  that `known` gives a symbol; `only_closure_of id s e` checks that the
  unit makes no closure of the code `id` but the static one bound to
  `s`. `FlambdaMyClosureProofs.v`: `only_closure_sound` (a unit that
  passes, run on its own, calls the code through the symbol only),
  `bind_my_closures_only_closure`, and the two statements of
  equivariance.
- `FlambdaLiftSpec.v`: the guess has one more field,
  `lifted_my_closures`; `lift_unit` applies `bind_my_closures` after
  `lift_expr` and checks `only_closures_of`; `lift_simulates_statement`
  has `known` and that check as a premise.
  `lift_unit_program_refines_statement` is unchanged, and both are
  proved again: where the code called has `my_closure` bound to a
  symbol the second run takes one step more, and the closure called is
  that symbol.
- `FlambdaValidateSpec.validate_unit rounds unused L before after` has
  a fourth verdict, `Same_once_lifted`: the term before, as given, is
  lifted by the guess `L`, then normalised, has its unused static
  bindings removed and is compared. `validate_unit_sound` is proved
  again; the statement under all environments does not cover the new
  verdict.
- The test tool guesses `L` from the term after
  (`tests/tools/flsemantics.ml`, `lifting_guess`).
  `tests/semantics/ocaml/exported_function.ml` is validated.

The series of the known symbols:

- `FlambdaKnownSymbolsSpec.v`: `known_bindings e` are the symbols that
  the unit binds, outside code, to constants with no variable in them;
  `fold_known` replaces, everywhere in the unit, a primitive or a
  projection whose arguments are constants and such symbols by its
  value, computed by `eval_named` itself under those bindings, where
  that is a constant or a symbol; `bound_as` checks that every binding
  of such a symbol in the unit is the one constant; `fold_known_unit`
  is the whole, extracted. Nothing is guessed.
  `FlambdaKnownSymbolsProofs.v`: `fold_known_unit_program_refines`,
  `fold_known_named_sound` (one defining expression, under any static
  environment that agrees with what is known), `fold_known_equivariant`.
- `validate_unit`: in the fourth check, each round of the normalisation
  of the term lifted is followed by this folding (`normalise_lifted`):
  a round puts a symbol where a variable stood for it, the folding
  resolves the projection, and the next round follows the result to
  where it is read in turn. No new argument.
- `tests/semantics/ocaml/exported_table.ml` is validated: an exported
  function whose code projects a constant pair of the module from its
  closure and loads a field of it that is a function. It is not
  validated if the folding is taken out. (A field that is a number
  shows nothing: the conversion from Lambda folds that load itself.)
  In `mutual_recursion.ml` the code of each function now calls the
  other through its symbol, as after Simplify.

The series of closures that hold a value computed when the unit runs:

- `FlambdaKnownClosuresSpec.v`: `use_known_closures e` replaces the
  projection of a value slot from a symbol by what the slot holds, and
  makes an indirect call of a symbol a direct call of its code, where
  the `Let_static` that binds the symbol to a closure has been passed
  on the way down (not in code, not in the handlers of recursive
  continuations). Under a binder of a variable the closures that hold
  that variable are forgotten. `FlambdaKnownClosuresProofs.v`:
  `use_known_closures_refines` (under all environments),
  `read_slot_named_sound`, `call_known_closure_sound`, and two
  statements of equivariance.
- `FlambdaFloatCodeSpec.v`: `float_code e` moves the bindings of code up
  over the `Let`s and the `Let_cont`s that they follow, to the head of
  the unit or of the handler that they are in.
  `FlambdaFloatCodeProofs.v`: `float_code_equivalent` (an equivalence
  under all environments), `float_code_over_let`,
  `float_code_equivariant`.
- `validate_unit`: in the fourth check each round of the normalisation
  of the term lifted is followed by `use_known_closures`, then by the
  folding on known symbols; and the two terms that are compared are
  first given to `float_code`. No new argument.
- `tests/semantics/ocaml/exported_capture.ml` is validated
  (`let base = opaque 10  let add x = x + base`). It is not if either
  pass is taken out. `tests/semantics/ocaml/exported_apply.ml` is
  validated (an exported function given to another, `apply succ 3`):
  the call of the argument, once `apply` is inlined, is a call of the
  symbol of `succ`.
- Each commit that changes `validate_unit` repairs
  `FlambdaValidatorEquivarianceSpec.validate_unit_equivariant_statement`
  (N3's) and its proof: the guess of the lifting is renamed with the

Liftings in turn:

- `validate_unit rounds unused slots Ls before after` takes a list of
  liftings. `FlambdaValidateSpec.lifted_in_turn` applies each in turn,
  each followed by the normalisation of a term in which something was
  lifted. A lifting after the first names `Let`s of the term that those
  before it give: those that the inlining of a call has brought out of
  a function, which Simplify lifts where it inlines the call.
  `validate_unit_sound` is proved again; its text has `Ls` for `L`.
- The rounds between two liftings are told not to make a name that is
  one of the two continuations of the unit (the corpus stream's
  repair, on a finding of the nominal stream). `lift_unit` and
  `lift_from_code_unit` check `well_formed_unit (lifting_unit L)` of
  the term lifted, whose checks of exception handlers go by the name
  of the exception continuation; a name that the normalisation made
  between two liftings could be that one where the term no longer
  mentioned it, and the next lifting was then not made.
- The tool guesses up to three liftings, each from the term that those
  before it give; one is tried after the first only if it lifts
  something. In its guess a variable whose own `Let` is lifted, or that
  is bound to a symbol or a constant, counts as that symbol or constant
  where the fields of a block are compared with those of a static
  block of the term after.
- `tests/semantics/ocaml/exported_made.ml` is validated
  (`let pair x y = x, y  let p = pair (opaque 1) 2`): the closure of
  `pair` is lifted in the term before as given, and the pair that the
  inlined call makes in a second lifting. With one lifting it is not.

The series of the lifting out of code:

- `FlambdaLiftFromCodeSpec.v`: `lift_from_code K lets at_path e` makes
  the `Let`s at the paths `lets` aliases of symbols, and rewrites every
  group of static bindings: in the body of the code that `K` names, the
  `Let`s that `K` gives for it are made aliases, and the static bindings
  that stand for them (`lifted_out_bindings`, by
  `FlambdaLiftSpec.lift_named`) are put in the group, before the code.
  Only a `Let` that mentions no variable is lifted out (`closed_named`).
  `lift_from_code_unit u K e` is `lift_from_code K [] root e` if `e`
  exits with symbols and constants only and the result is a well-formed
  unit.
- `FlambdaLiftFromCodeProofs.v`: what `lift_from_code_unit` gives
  refines the unit, run on its own
  (`lift_from_code_unit_program_refines`); the rewrite commutes with
  renaming. The simulation is in step. `FlambdaLiftProofs.v` has its
  lemmas about lifted values stated with what they need of the two
  static environments (`symbols_lifted`), so that they serve both.
- `validate_unit` applies it in each lifting, before `lift_unit`
  (`with_lifting`): the guess has a field more, `lifted_out_of_code`,
  the `Let`s to lift out by code id and by their paths in the body.
  Each of the two is made where its conditions hold. No argument of
  `validate_unit` changes, and no statement of it. The nominal stream's
  files have what they need of it: `lift_from_code_unit_renamed`, and
  that the rewrite keeps scope (`lift_from_code_keeps_scope`).
- The tool guesses the `Let`s to lift out: a symbol of the term after
  that no `Let` outside code takes goes to the first `Let` in the body
  of code that makes just what the symbol is bound to and mentions no
  variable.
- `tests/semantics/ocaml/exported_fun_given.ml`
  (`let with_succ use = use (fun x -> x + 1)`) and
  `exported_fun_returned.ml` (a function that returns a function of

- With that wiring, which leaves the calls of the code that it is

The series of the arms of a test:

- `FlambdaLiftFromArmsSpec.v`: `lift_to_head lets e` makes the `Let`s
  at the paths `lets`, outside code, aliases of symbols
  (`FlambdaLiftFromCodeSpec.lift_from_code`, with no code named), and
  binds the symbols in one group around the unit
  (`lifted_out_bindings`). Only a `Let` that mentions no variable is
  lifted. It is for the `Let`s of the arms of a test that is not
  resolved: handlers that are not at toplevel, where no static binding
  may stand. `lift_to_head_unit u lets e` is that, if `e` exits with
  symbols and constants only and the result is a well-formed unit.
  `FlambdaLiftFromArmsProofs.v`: `lift_to_head_unit_program_refines`,
  by the simulation of the lifting out of code, and
  `lift_to_head_equivariant`.
- `FlambdaHoistStaticsSpec.v`: `hoist_statics u e` binds first, in one
  group around the unit, the bindings of code and the bindings of
  symbols whose constant has a value in the empty environment
  (`is_hoisted`: it mentions no variable), taken from the groups of
  the toplevel of the unit, in handlers too (`hoisted_bindings`,
  `without_hoisted`). It answers `None` unless the unit is well
  formed, imports nothing, and has every static name in scope where
  it is mentioned: row 4 of well-formedness
  (`FlambdaStaticsInScopeSpec.statics_in_scope [] e`, with
  `interface_conts_not_rebound` and `static_names_apart`).
- `FlambdaHoistStaticsProofs.v`: a unit that passes and the unit with
  those bindings first, each run on its own, are equivalent
  (`hoist_statics_program_equivalent`). The two runs are in step with
  equal values. The second has all the code and the symbols taken out
  bound from the start; the invariants of row 4 on the first run
  (`terms_inv`, `state_statics_bound`) say that it never looks up or
  calls a name that it has not bound yet, so the second finds what
  the first finds. The two parts commute with renaming.
- `validate_unit`: `with_lifting` makes the lifting to the head, then
  the lifting out of code, then `lift_unit`; the guess has a field
  more, `lifted_to_head`. A fifth comparison follows the fourth: the
  two terms each with its static bindings that need nothing bound
  first (`with_statics_first`, for the unit of the first lifting).
  Simplify binds the symbols that it lifts out of the arms of a test
  under a `Let` before the test, the term before has them at its
  head, and with the bindings of both first the place does not
  matter. No argument of `validate_unit` changes, and no statement of
  it; the verdict is `Same_once_lifted`. Where `hoist_statics`
  refuses a term, `with_statics_first` leaves that term as it is, and
  the comparison is still made. The first four comparisons are as
  they were, and a guess as it was, with nothing to lift to the head,
  gives the term that it gave. That is not a statement about the
  guess of the tool, which has changed: of that the tests are the
  measure, and no `.expected` file of a unit that was a test moves.
- The nominal stream's files have what they need of it:
  `lift_to_head_unit_renamed`; `hoist_statics_renamed`, with that
  `statics_in_scope`, `interface_conts_not_rebound` and
  `static_names_apart` answer the same on a renamed unit;
  `with_statics_first_renamed_alike`; `lift_to_head_keeps_scope` and
  `with_statics_first_keeps_scope`. `lifted_in_turn_up_to` now also
  says that the renaming it gives renames the continuations to avoid
  as the first does: the fifth comparison checks the term lifted by
  the continuations of the unit.
- The tool guesses the `Let`s to lift to the head: in a handler that
  is not at toplevel, a symbol of the term after goes to the first
  `Let` that makes just what the symbol is bound to and mentions no
  variable. The paths of the `Let`s that `lift_unit` lifts are then
  given as they are under the group that the lifting to the head
  makes.
- Nine units with a closure in the arm of a test made when the
  module runs are validated, and none was before
  (`tests/semantics/ocaml/exported_fun_in_arms.ml` and those after it
  in the README): a function in each arm; in one arm; after a `Let`;
  two tests in sequence; a function chosen by a test and called by a
  function defined after it; an option, a pair and a record that
  hold a function made in the arm, in two liftings (the block is
  lifted once the closure is a symbol); and a match of three cases
  (`exported_match_three_funs.ml`), where Simplify binds the symbols
  below the handler of the inner test, which mentions them: row 4
  has what the body of a `Let_cont` binds in scope in its handlers.
- The lifting out of code and the lifting to the head go into
  loops, and two `Let`s of one constant may share a symbol.
  `FlambdaLiftFromCodeSpec.lifted_out_bindings` and `lift_from_code`,
  which both liftings use, go into the handlers of recursive
  continuations: a `Let` that mentions no variable makes the same
  thing each time round. The path of a `Let` in such a handler is
  under that of the handler (`FlambdaLiftSpec.rec_handlers_map`: the
  handlers of the group bound at `p` are at `p~1~0`, `p~1~1~0` and so
  on). The bindings that stand for the `Let`s lifted out of one body
  are put once each (`once_each`): a binding is left out if one
  before it binds the same symbol to the same constant, the same
  term. A guess that gives one symbol to two `Let`s that differ
  leaves both bindings, the symbol is bound twice, the result is not
  a well-formed unit and the lifting is not made. Nothing is shared
  between two bodies. No statement changes and none is added:
  `lift_from_code_unit_program_refines` and
  `lift_to_head_unit_program_refines` are proved for the wider
  functions, with their renaming, and the scope lemmas of both in
  FlambdaStaticsScopeProofs.v. In the proof, what a `Let` lifted out
  needs is that the bindings that stand for it are evaluated,
  whichever `Let` they were put for (`bindings_bound`,
  `bound_alias`), and a closure of a handler of a recursive group
  carries the group rewritten.
- The tool guesses these: in the handler of a recursive continuation,
  in code or outside it, a symbol of the term after goes to the first
  `Let` that makes just what the symbol is bound to and mentions no
  variable, and a later `Let` in the same place that makes just what
  a symbol given there is bound to takes that symbol too. The
  recursive call of a local function through its symbol is what
  `lift_unit` did already (`bind_my_closures`).
- Three units are tests and were not validated before
  (`tests/semantics/ocaml/loop_function_in_kept.ml`: a function that
  captures nothing, made at each round of a loop in a function that
  is kept; `local_rec_in_tail_loop.ml`: a local recursive function

  position; `loop_function_twice.ml`: a function with such a loop
  inlined twice when the module runs, one symbol for the two
  closures). No `.expected` file of a unit that was a test moves.
- The validator removes the `Let`s that the removal of value slots
  leaves unused (`FlambdaValidateSpec.without_slots`). The slots go
  after the last round, so a `Let` whose only use was a slot that is
  removed stayed in the term before: the closure of a function that
  another closure held in a slot and called through it, once that
  call is inlined. Simplify removes the slot, the closure and its
  code. `without_slots` is now the removal of the slots followed by
  `remove_unused_lets`, in the term and in the bodies of its code;
  the code is then a static binding that nothing names, which
  `without_statics` removes. No statement changes:
  `without_slots_program_refines`, `without_slots_keeps_scope` and
  `without_slots_equivariant` are proved again. Two units of the
  shape are tests and were not validated before
  (`tests/semantics/ocaml/helper_inlined_in_closure.ml`: a helper that
  the unit does not export, inlined in a function that is never
  inlined and that also uses a value of the unit that is not known;
  `hidden_helper_inlined_twice.ml`: the helper hidden by the
  signature of a module and inlined in two functions). No `.expected`
  file of a unit that was a test moves. It was the order only: no
  rewrite was missing.
- The groups of static bindings go above the continuation bindings
  before the terms are compared. `FlambdaGroupsUpSpec.groups_up` binds
  a group that is at the head of the body of a `Let_cont`, recursive
  or not, before the `Let_cont` instead, outside the bodies of code
  and the handlers of recursive continuations, and makes one group of
  groups that then follow one another. It is an equivalence under all
  environments and commutes with renaming. It is the last step of
  `FlambdaValidateSpec.tidied_before` and `tidied_after`, after their
  rounds, which can remove a `Let` that stood between a `Let_cont` and
  a group. By itself it turns no unit: with it and without it the
  tool gives the same output on every unit of the tests and on the
  units that were measured. It is there for the lifting to a group
  around, which binds a group before a `Let_cont` where Simplify has
  it below.
- The lifting to a group of static bindings around
  (`FlambdaLiftAroundSpec.v`). A `Let` of a closure, an immutable
  block or a boxed number is made an alias of a symbol that a group of
  static bindings around it binds to what the `Let` makes. Three
  things that Simplify does are followed with it: a block or a
  closure made in the arm of a test, with a field or a value slot
  that is a variable bound before the test, is a symbol bound before
  the test; the same in a loop; and a `Let` that makes what a symbol
  of the unit is bound to already is that symbol, so two equal boxed
  numbers or blocks are one symbol. `lift_around` makes the `Let`s at
  the paths given aliases and puts groups before the `Let_cont`s at

## How the proof goes

A simulation in which each step of the first run is answered by one or
more of the second (the lifted `Let` takes two; so does a call of code
in which `my_closure` is bound). The relation: the second expression is
the first lifted, values are related by `value_lifted`, and every
symbol the first run binds the second binds to the same thing, lifted
(`statics_lifted`); code is related by `bind_my_closure`. The second
run is that of a well-formed unit, so it never binds a symbol twice
(`well_formed_never_faults`): that is the only use of well-formedness.
That the closure called is the symbol is an invariant of the second
run alone (`only_closure_sound`). Equality at the exit is from an
invariant of the first run alone (`plain_state`).

  and it is proved. Once exits are compared through the heap (C4's
  epoch) it is not: the term before holds a symbol bound to nothing
  where the term after holds one bound to the closure. At that
  migration `lift_unit` is to check that the symbols it gives do not
  occur in the term before; it is not to become a premise of
  `validate_unit_sound`.

## Not covered (the unit is then "not validated")

- One symbol for a `Let` in the body of code and a `Let` outside it,
  or in the bodies of two pieces of code. (One symbol for a `Let`
  outside code and a constant that the unit binds already is the
  lifting to a group around.)
- Lifting out of an arm in a unit that mentions a symbol it imports:
  `hoist_statics` asks `statics_in_scope` with no import.
- The sharing of equal constants in the body of code: the lifting to
  a group around does not go into code.
- In code, one variable of the unit read twice, through value slots
  of two static closures or a slot and a field of a static block:
  Simplify reads it once.
- Anything with identity: a block that is mutable or unique, a
  mutable array.
- An immutable array of the source that only a later lifting gives a
  symbol (one whose elements are closures that are lifted first, or
  one made an alias of a symbol bound around it): the guess of the
  first lifting takes the array of the term after for a table of
  Simplify's, and the unit may stay not validated. It is not said
  that it does: where the table is bound at the head of the term
  before, a later lifting may make the `Let` an alias of it.
- A value slot of a static closure read twice where Simplify reads it
  once: the validator inlines, in the code of a function, two calls
  of a function whose closure holds a value computed when the unit
  runs, and each inlined body reads the slot; Simplify shares the
  two reads. The normalisation shares no primitive
  (`exported_branch_calls_twice.ml`; said to the corpus stream).
- A primitive applied to a constant of the unit that the validator
  computes and Simplify does not (a byte of a constant string,
  `string_get_checked.ml`): the side before then knows more than the
  side after. The same folding on the side after is an equivalence
  only where the symbol is bound when it is read, which is row 4
  again, or for a symbol whose `Let_static` is in sight.
- The wrapper that Simplify makes of a partial application, which
  calls the function through a value slot of its own closure
  (`partial_exported.ml`, and `let add_two = compose succ succ`): the
  validator knows what the slot holds and inlines the call on the
  side before. The corpus stream's table has it.
