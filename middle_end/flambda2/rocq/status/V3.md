# V3: lifting to symbols, for the validator

Branch `flambda2-rocq/V3-lifting`. (The roster's V3; not the converter
of `OWNERS.md`'s section V3. The files are listed under S5 there.)

## Aim

Units in which Simplify makes a closure, an immutable block or a boxed
number a symbol are validated by `validate_unit`, not only compared on
one run.

## How the proof goes

A simulation in which each step of the first run is answered by one or
more of the second (the lifted `Let` takes two; so does a call of code
in which `my_closure` is bound). The relation: the second expression is
the first lifted, values are related by `value_lifted`, and every
symbol the first run binds the second binds to the same thing, lifted
(`statics_lifted`); code is related by `bind_my_closure`. The second
run is that of a well-formed unit, so it never binds a symbol twice
(`well_formed_never_faults`): that is the only use of well-formedness.
That the closure called is the symbol is an invariant of the second
run alone (`only_closure_sound`). Equality at the exit is from an
invariant of the first run alone (`plain_state`).

## Decided overnight (for the human)

- The validator accepts lifting only for a unit that exits with symbols
  and constants (`exits_plain`). Options: (a) this check, keeping
  equality at the exit; (b) compare exits through symbols (D1, D6),
  which changes what `validate_unit_sound` says. Chosen: (a), with a
  note for the human at `exits_plain` (the CR rule of the plan). To
  change: delete the check and use `lift_simulates` as the statement.
- A `Let` to lift is named by its path in the term, not by its
  variable: two `Let`s of one variable are told apart, and the pass
  commutes with renaming as it stands. To change: the type `path` and
  one argument of `lift_expr`.
- The lifting is applied to the term before as it is given, and the
  result normalised once. The other order (normalise, lift, normalise)
  was the first version: it unfolded recursion twice, a `Let` in a
  function inlined several times was several `Let`s, and a closure
  that nothing uses was gone before it could be lifted. To change: one
  line of `validate_unit` and of its proof. A second lifting after the
  normalisation, for a block that exists only once calls are inlined,
  would be one more verdict.
- "`my_closure` is the symbol" is part of `lift_unit`, not a pass of
  its own with a theorem of its own: on its own it is no refinement
  (the closure called is a closure before the lifting and a symbol
  after), so the two are one simulation. Its definitions, its check
  and what is true of the check alone are in `FlambdaMyClosureSpec.v`.
  To change: nothing is lost; a separate theorem would need the
  relation `value_lifted` again.
- `bind_my_closures` binds `my_closure` again by a `Let` in the body
  and leaves the substitution to `follow_aliases`. If N1's conditions
  on binders come to forbid binding a name that is already in scope,
  it has to substitute instead; said to N1.

## Not covered (the unit is then "not validated")

- Lifting out of a function or a loop, where the binding moves to
  toplevel. Simplify does this for a constant whose parts are constants
  and symbols (discrepancy V3-2).
- The sharing of equal constants.
- Immutable arrays; anything with identity.
- A projection of a function slot from a symbol
  (`Project_function_slot f g (Symbol s)`, which Simplify makes the
  symbol of `g`): needed by `mutual_recursion.ml`, where each function
  projects the other from `my_closure`.
- The value slots of a static closure that nothing projects, which
  Simplify removes: a unit in which an exported function calls another.
- What is not the lifting's, seen on units that export functions: a
  call that Simplify leaves (the function is too big to inline) is
  inlined by the validator on both sides, and the term after is left
  with the continuation of the call (V2's list of calls not to inline
  could name every code that the term after still calls); the
  continuation that makes the module block, applied in the handler of
  another (V4's); a tupled function called indirectly (V2's table).
