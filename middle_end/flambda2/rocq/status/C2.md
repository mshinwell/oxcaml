## Decided overnight (2026-11-13), for the human to review

- What the scripts refuse for the grouping of an arity (labels C2-5
  and C2-30). The question: the text groups neither the arguments of a
  call nor the parameters of code, and writes nothing for a component
  of no kind; which units are the scripts that make the texts to
  refuse? The options: (a) wide: a unit that has a call of unknown
  arity is refused if such a call has an unboxed product among its
  arguments, or code of the unit has one among its parameters,
  whatever the product; (b) narrow: only where the product has no
  value in it (the product of nothing, or a product all of whose
  fields are such). The choice: (a), agreed with the orchestrator.
  Why: (a) needs no argument about the compiler's terms and refuses
  no unit of the tree. (b) rests on this: where every component has
  at least one value, and the call and the code agree component by
  component as far as both go, the numbers of values of the call and
  of the code compare as their numbers of components do, since what
  they share counts the same in both and each further component
  counts at least one; so a full application, a partial application
  and an over-application are read as what they are. That takes the
  agreement of the call with the code as a premise, which the
  compiler does not see to, and takes the scripts to recognise, in
  what the compiler prints, every product that has no value in it.
  And it holds of a call and of code that are both read from the
  text: code that the tool takes from the `.cmx` of another unit has
  its components, and a call read from the text against it is counted
  by its values, whatever the product (two units of the same measure,
  with a pair of two fields: undefined in both runs where the
  compiler's own terms are right). What (a) costs, measured outside
  this tree: it refuses 78 of 6,285 units of other sets, and 69 of
  112 units written to apply functions with unboxed products, of
  which the tool printed of 12 a run that is not the program's,
  through the text, each with a component of no kind; (b) would
  refuse 40 of the 112, those 12 among them. What it would cost to
  change: the awk of the two scripts with their test, and the
  sentences of the ledger; nothing in the tool.
- Named function slots in every unit (labels C2-22 and X4-3), asked
  by the orchestrator: done in the tool alone. The first presentation
  of a set stays in the model, where 144 items of 47 `Spec` files name
  one of its five forms (counted on the text of the files, in the
  stack before this one); deleting it there is a change of the model
  for the human to order.

## The prefix: what the `.cmx` files say of other units

Step 2 of `requests/C5-imports-with-contents.md`, in
`tests/tools/flsemantics.ml` (`make_prefix` and what is around it). No
`.v` file changes with it, and it is under no theorem of its own: it
is trusted OCaml, and the header of the tool says what is trusted of
it.

Done:

- After Simplify has run, the two terms of a check are given one
  prefix of static bindings, the same in front of both, made from the
  `.cmx` files of the units that the run read and of no other, through
  the compiler's loader and its reduction of the type of a symbol
  (`Flambda_cmx.load_symbol_approx`). It opens no file that the run
  did not read; of those files it may read the body of code that
  Simplify did not look at. It binds the data that the files
  reach, through fields, from the blocks that the two terms ask for (a
  block of values whose fields are constants and symbols; a closure at
  its function slot, alone in its set, with no value slot), and the
  bodies of the code that is asked for. The comment above
  `make_prefix` has the rule, which is that of section 3 of the
  request.
- What is not bound stays an import, or a code id bound to nothing: a
  block with a field of which nothing is said, code with no body in
  the file, tupled code, a body that the model has not got. A symbol
  that the file says is another symbol or a constant is refused.
- The prefix is checked before it is used: each name bound once, none
  that either unit binds, none still among the imports, and the groups
  evaluate from the static environment of the imports. A failure is
  reported as a fault of the conversion. A term after Simplify that is
  well-formed alone and not with the prefix in front is reported as
  that, and not as a term that Simplify made ill-formed.
- It is printed before the two runs, with the compiler's names, for
  reading against the other unit; what is bound without being asked
  for is counted on one line for each block that it is reached from.
  The line of the verdict says of how many units the files were used.
- A unit for which no `.cmx` file was read has no prefix and prints
  what it printed.

The pairs of `tests/semantics/ocaml/pairs/` are checked with it: five
of the seven second units have a prefix, and their expected files
changed with it (`pairs/README.md` says what each shows).

Measured as well, on units that are not in this tree: pairs of units
written by hand, each at the default flags and at `-O3`. A call of a
function of the other unit, at toplevel and in a function, inlined
or not; a function of a nested module; one reached through an alias
of a module; `include` of the other unit; fields read and kept; a

validated with its prefix at the default flags, and the two runs are
defined and the same wherever the body called is in the file. At
`-O3` the last is not validated, for what Simplify does there with
the loop of the second unit itself. A call of code that has no body
in the file is undefined in both runs, and the validation then says
nothing. A module block with a field of which the file says nothing
(a value computed when the module is initialised, a closure that is
the result of a call) is not bound, and the unit is as it was
without a prefix: this is every unit that goes through the module of
the standard library that is opened at the start, until the model
can say that nothing is known of a field.

## What the text of a term loses of a call

Not in the integration branch when this was written.

The arity of a result. A call of unknown arity is printed with no
arity and read with one value for its result (label C2-5). Where the
compiler's call returned an unboxed pair or an unboxed number, the
term read has a call that returns one value to a continuation of two
parameters, or of one parameter that is not a value, and the tool's
Simplify stopped on it with a fatal error: `Invalid_argument` out of
`simplify/env/continuation_uses_env.ml`, where `add_continuation_use`
goes down the types of the result and the parameters together, or
"Kind mismatch upon meet" (label X5-12; X5 found it on two units
made from OCaml sources). The tool now tests the text as the parser
gives it (`result_arity_lost`; it goes by the identifiers of the
parsed text and makes no name of the compiler, so no expected file
moves) and, where a call of unknown arity returns to a continuation
in sight whose parameters are not one value, prints "not checked"
with the reason and does not run Simplify. A call is of unknown
arity as the reader has it: no arity written, or the arity of the
result written alone, which the reader drops. In sight means bound
by a `Let_cont` around the call, a name bound again hiding the one
before, or the return continuation of the code that the call is in.
The round trip is given the same reason. The arguments of such a
call are as before: the run of the term read is undefined where the
code called takes other kinds.

Examples, in `tests/semantics/`. The compiler's terms of X5's two
units: `unknown_arity_result_pair.fl`, `unknown_arity_result_int64.fl`.
Ten written by hand for the edges of the test, `arity_text_*.fl`.
Not checked: `no_parameter`; `result_arity_alone` (the arity of the
result written, that of the arguments not); `hidden_by_two_values`
(an inner continuation of two parameters hides an outer one of one);
`return_of_code` (the return continuation of code whose result is
two values); `recursive_invariant` (a recursive continuation with an
invariant parameter). Checked as before, each with a run that is
defined, and validated: `full_arity` (both arities written, two
results); `hidden_by_one_value`; `code_in_handler` (code bound in
the handler of a continuation of two parameters, whose own return
continuation has the same name); `recursive`; `never_returns` (a
call that never returns, beside a continuation of two parameters).

Probes. The conversion refuses a call that is a probe
(`convert_apply`, by `Unsupported`, before anything else of the call
is read). The program runs the handler of a probe only while the
probe is enabled; the model has no notion of that and would run it
always. The refusal goes by the mark that a term in memory has. The
text of a term has no such mark and its reader gives none: a unit
that has a probe of its own is read as a unit with a plain call and
is checked as one, and the refusal does not detect that. A term in
memory may have the mark, and the prefix converts such terms: the
bodies that it takes from `.cmx` files.
Before this change the prefix bound a body with a probe with the
handler's call as a plain call. In the pair written to show it, the
tool of the commit that brought the prefix printed a prefix of six
bindings, the body among them with the call of the handler; both
runs were undefined there (the handler calls a function whose code
has no body in the `.cmx`), so no verdict was wrong by it. That
says nothing of a pair where the runs are defined: taking a probe
for a plain call was a mistake of the conversion, not a harmless
reading. Now the conversion of the body fails, `bind_code` of
`make_prefix` leaves the code unbound as it does for any body that
does not convert, and the unit is not refused for it: the closure
is bound, a call of it is undefined. Where the tool's Simplify
inlines such a body into the unit, the term after has the probe
and the unit is not checked. The pair is in the tree:
`tests/semantics/ocaml/pairs/probed.ml` and `probed_called.ml`,
with `probed_inlined.ml` for the second way. Label C2-17.

Phantom bindings (a later series; not in the integration branch
when this was written). The conversion refuses a binding whose
variables are phantom (`convert_let`, before any of its cases, so
that the bindings of regions and of depths, which are dropped, are
covered too). The program runs nothing for such a binding: the
backend compiles its body alone. The model runs every `Let`. With
`-g` and phantom lets on (`-flambda2-expert-phantom-lets`, which
`-gdwarf-may-alter-codegen-experimental` also sets), Simplify may
keep an unused binding as phantom instead of deleting it; the term
that the compiler gives to Simplify has none. The text of a term
does not say the mode, and the reader gives the normal one: the
refusal cannot detect a phantom binding whose mode a text has lost,
as for probes. A term in memory has the mode: a body taken from the
`.cmx` of a unit compiled with those flags, and the term after when
the tool is given them. Before this change the conversion did not read the mode
and converted the binding as a `Let` that runs. In the pair written
to show it, the body of a function has a phantom load of the first
field of its argument, the code made of it loads nothing, and a
unit calls it with the number 0: the prefix bound the body with the
load, and the run before was undefined at the load, where the
program returns 0. On a run where the term before is undefined, any
term after refines it in the model, so the theorem of a validation
says nothing of the term after there, and this reading could
conceal a wrong term after (which is not to say that the validator
accepts every such pair); the pair did not show one, and nothing
wider was measured. Now the body is left out of the prefix, as any body that
does not convert, and a unit whose term after has such a binding is
not checked. The pair is in the tree:
`tests/semantics/ocaml/pairs/phantom.ml` (compiled with the two
flags, by a line of the source that the rules read, and checked
with them: not checked) and `phantom_called.ml`. Label C2-19. It
was found by reading the conversion against every field of the
terms, which the table below was not.

What else a term in memory has that a text cannot say, and what the

## The symbol of the unit, and what the text loses of a primitive

Not in the integration branch when this was written. Three changes
to the test tool and one to the rules of the tests.

The symbol of the unit (label C2-21). Other units read the data of
the symbol of a unit; the backend does not use what the unit gives
its return continuation; the model observes what it is given there.
The tool now checks a unit only where, in the term before and in the
term after as they are written, every use of the return continuation
of the unit gives it the symbol of the unit and nothing else, and no
call returns to it (`return_not_of_own_symbol`, asked in `check`).
A unit of which either term fails is "not checked", with the reason,
and the tool ends without an error. It is a test of the form of the
term: a unit that returns its own symbol through a variable or from
a call is refused all the same. Three units written by hand,
`tests/semantics/returns_*.fl`. No other expected file changed; no
unit of the corpus made from OCaml sources, of the pairs or of the
two census sets (not in this tree) is refused by it.

The kind of an opaque identity (label C2-27). The text of a term
does not write the kind of an `Opaque_identity`, and the reader
gives the kind of values, so a unit that applies the primitive to a
naked number was read as a term that is undefined in the model; the
tool's Simplify made such a unit `Invalid`, and the tool printed a
validation that said nothing. The tool now normalises a unit read
from a text (`with_lost_kinds`, which was `with_opaque_kinds` until
it gave a call the arity of its arguments too; see the section on
the reader of a text): each `Opaque_identity` is given
the kind of its argument, the variable that the reader bound to it
at the kind of values is replaced by one of that kind, and so on
down the unit, in handlers and in the bodies of code. A unit that
has no such primitive at another kind than its argument's is not
gone through (`kind_lost_in_expr`, which looks at the unit
as a term is opened for printing). The round trip of the conversion
normalises the unit of the file and each unit that it reads back.
What it is not: a check of kinds. The kind given is the compiler's
where the kind obtained for the argument is the argument's kind in
the compiler's term and the primitive there had that kind; the
first can fail where the compiler's term binds a variable at another
kind than that of its defining expression (label C2-24) or has an
`Opaque_identity` above at another kind than its argument's. It is
applied to a unit read from a text only. Where the argument's kind
comes from a nullary primitive at one of the two kinds that the
reader's table gives for two words each (`parser/fexpr_prim.ml`,
`kind`: `int32` is read as a naked `int8` and `int64` as a naked
`int16`), the unit is not checked. Units, in `tests/semantics/`:
`kinds_opaque_naked.fl`, `kinds_opaque_handler.fl`,
`kinds_opaque_in_code.fl`, `kinds_opaque_pair.fl` (each undefined
before this change, with a validation that said nothing; each now
returns, the same before and after, validated) and
`kinds_opaque_misread.fl` (not checked). One expected file that was
there changed: `kinds_opaque_bad.fl` was an opaque identity at the
kind of values on a naked number, which no text says any more; it
is kept by name with a block made of the naked result between, so
that it is still a primitive on an argument of another kind that is
executed (undefined before and after, one step later). Measured
with the tool of this change over the corpus made from OCaml
sources and the two census sets: no output changes. A first
version went through every unit and made fresh names in each; two
expected files of the corpus moved, in the stamp of a variable
printed in a "not checked" line, which is why the unit is looked at
first.

The flag of `Is_int` (label C2-26). The text writes the two forms of
`Is_int` alike and the reader gives the form that is for variants;
on a value that is not a variant, a closure for one, the term read
is undefined in the model where the program gives 0. The tool does
not put that right: making every `Is_int` of a text the other form
was measured and loses validations (30 of the 1,187 units of the
corpus and the two census sets, none gained), as the validation
uses what the form for variants says. Instead a unit whose term has
the other form does not enter the tests unseen: `from_ocaml.sh`,
in `tests/semantics/ocaml/` and in `pairs/`, compiles each unit
once more for what `-drawflambda` prints of the term before
Simplify and fails if it has `Is_int_generic`, unless
`generic_is_int.txt` beside the sources names the unit. Both lists
are empty: no unit of the two directories has the form (51 of the
347 sources of the corpus have the form for variants). A name may
be added only with what makes the tool say of the unit that it is
validated for the term as read.

### How to read a row

What the conversion does with a field:

- **faithful**: the model's term has the field, with the compiler's value.
- **claim kept**: the field promises something of the run, and the model
  makes a run that breaks the promise undefined.
- **refused**: the conversion stops (`Unsupported`); the unit is "not
  checked", or the body is left out of the prefix. The message is given.
- **dropped**: left out knowingly; the ledger says so.
- **not read**: the conversion does not look at the field, so the term
  of the model is the same whatever it holds.

For a field that is dropped or not read: **S** means that what Simplify
makes of the term can depend on it, **M** that what the program does can
(what the backend makes of the term). Then the way the tool can be wrong
by it:

- **faults**: the tool can fault a Simplify that is right ("not
  validated", "DIFFERENT");
- **silent**: the tool says nothing where it could ("not checked", or a
  validation of a term that is undefined in the model);
- **hides**: a validation can pass over a term after that is wrong;
- **none**: the term of the model and what the program computes are the
  same whatever the field holds.

A field with S and no M matters to whether the tool's run of Simplify is
the compiler's run. That is the reading of the text, not the
conversion, and is "none" here.

A probe (label C2-17, for a unit read from its text). The conversion
refuses a call that is a probe in a term in memory. A unit whose own
source has a probe reaches the tool with the mark gone, as a unit
with a plain call. Two units not in this tree: where the handler of
the probe raises, the program does not call it and returns, and the
tool printed "raises" for both runs of the unit read; where the
handler does nothing, the tool printed the right result and a bare
"validated", of a term in which the handler is always called. No
unit of the tree had a probe with an expected file. `from_ocaml.sh`
(in `tests/semantics/ocaml` and in `pairs/`) now refuses a unit whose
term, as `-drawflambda` prints it, has a call marked `(probe NAME)`;
in `pairs/` only where the unit has an expected file, so that
`probed.ml` is still compiled for its second units.

The arity of the arguments of a call (label C2-5). A unit that gives
a function an unboxed number was undefined in the model as read: the
reader gives a direct call and a call of unknown arity one value for
each argument. The pass of the tool over a unit read from a text,
now `with_lost_kinds`, gives each such call an arity
(`arity_of_arguments`). A direct call has the kinds of the
parameters of the code that it names, where the unit binds the code
and the numbers agree: the conversion from Lambda makes a call
direct only where its arity is that of the code
(`close_exact_or_unknown_apply`). Otherwise the unit is not checked
if an argument is not a value. A call of unknown arity has one kind
for each argument, the kind that the term read has for it, with the
refusal of the opaque identity. That is the arity of the compiler's
call, subkinds aside, on three conditions, none of which the tool
checks, which suffice together and are not necessary: the kind
obtained for each argument is its kind in the compiler's term; the
arity of the compiler's call gave each argument its kind; and that
arity had one singleton component for each argument, with no
component that is an unboxed product. A unit that has
no call to change and no opaque identity to change is not gone
through.

The grouping (labels C2-5 and C2-30). The arity given is flat, one
component for each argument that the text writes, as the reader's
was. In the compiler's arity an argument that is an unboxed product
is one component, and an application counts the components against
the parameters of the code to tell a full application from a partial
application or an over-application. The text groups nothing, at a
call or in the parameters of code, and for the product of nothing it
writes no argument and no parameter. So a partial application that
stops before a parameter of no kind is read as a full application,
and so is an over-application whose last argument has no kind. Two
units not in this tree, with the tool as it was and as it is, since
every argument that the text writes is a value: of the first the
tool printed an integer where the program has a closure, of the
second a closure where the program has an integer, each with a bare
"validated". The tool cannot tell: the text of such a unit is that
of a unit without the parameter or the argument of no kind. The loss
is the text's alone: the driver of the compiler's own run takes the
two terms from memory, where the component is, the conversion keeps
it as an unboxed product of no component, and of the same two units
that driver has the closure and the integer that the programs have.
The refusal is in the scripts, and does not protect a text that is
given to the tool by hand. The same loss gives a false alarm where
the code comes from the `.cmx` of another unit, with the component
that the call was written without: a unit not in this tree, compiled
rightly, of which the tool printed "DIFFERENT" (the ledger has it,
with a measure of 112 units made outside this tree). So
`from_ocaml.sh` refuses a unit that has a call of unknown arity, if
such a call has a product among its arguments or code that the unit
binds has one among its parameters, the product of nothing
included. In a unit that it lets through no call of unknown arity
has a group, and neither has the code of the unit, which is all that
such a call reaches of what is read from the text; code of another
unit comes from its `.cmx` with the arity that the compiler gave it.
A unit that has only direct calls is not refused: a direct call has
the parameters of its code, flattened as the call is. The script
also refuses a unit of which `-drawflambda` does not print a call
or code as it expects.

Two things seen there, neither a wrong verdict. A term after that
names a symbol of the other unit which its `.cmx` has not got ends
the tool on a fatal error of the compiler, which the tool does not
catch; no term that the compiler makes has that. And one prefix goes
in front of both terms, so a load in the term after that the test
sees leaves the block unbound for the term before too: the line
"nothing to validate, as the term before is undefined" can then be
of a term before that has a run where the term after has no such
