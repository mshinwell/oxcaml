# C1, primitives as data: status

The request, `requests/C1-primitives.md`, is accepted by C0 and signed
off by R1. The text R1 read was a prototype, with the commits in the
order they were made.

The first epoch is applied: the two moves, primitives as data at the
first stage, the note, and the test tool with the examples of that
stage, the last by C0 with the regenerated extracted files. After it,
as leaves, each on the one before: this file and the fourth law
(0c24018933, 47f3819f23), the second stage (1301aa5104, a9cb7aaac8) and
the third (c8c81254fd, 5ed48f2c6a). Each stage is two commits: the
three files of the primitives, then the converter and its examples,
which C0 applies with the regenerated extracted files. At the end of
the third stage the files of the primitives, the converter and the
examples are those of the prototype that R1 read. All of it is on the
integration branch, the three leaves included.

After the leaves, two commits (5c1a7c1572, 423bbe23e5): the CRs, and
the ruling on symbols that are not bound.

## Agreed with other streams

- T1: the value forms `Value_block (tag) (fields)` and
  `Value_boxed_number (contents : const)`; the observations `block_of`,
  `boxed_number_of`, `string_of` (taking the static environment, as
  `closure_of`) and `kind_of_value`, defined by C1 and used by the types;
  `Is_int` has the compiler's `variant_only`, and with it is defined on
  tagged immediates and blocks only; `Get_tag` on blocks only; `Is_null`
  on null, tagged immediates and allocated values. `boxed_number_of`
  goes by the kind of the contents, so a boxed poison is a boxed number
  and allocated: `Is_null`, and `Is_int` without `variant_only`, answer
  0 on it, while unboxing it and boxing a poison have no value; T1 uses
  `boxable_number_of_kind` in place of its boolean `boxable_number`, and
  C1's `observations_disjoint` in place of its own. The relations that
  types record stay T1's definitions (R1 found them wider than the run
  of the primitive); each contains the graph of its primitive, which S1
  is to prove from the lemmas of `FlambdaPrimitiveProofs.v`. T1
  recommends, for the human: `Is_null` 0 on any symbol, bound or not,
  and no value on poison; the prototype has no value on either.
- C2: `prim_result_kind`, `prim_args_well_kinded`, `kind_of_value`,
  `kind_eqb`; the law that a primitive with a value had well-kinded
  arguments and has a value of its result kind; kinds move to
  `FlambdaKindModel.v`, where C2 adds arities in its epoch.
- C3: `Project_value_slot` stays in `named`, and so does the projection
  of a function slot; closures are read through `closure_of` only;
  `Phys_equal`, when added, has no value on anything allocated.

  as GADTs give legitimate terms with kind mismatches. The design
  assumes no static well-kindedness (the request, decision 7); that the
  model's test on values agrees with Simplify's on types does rest on
  C2's well-kindedness, or on the code not being run.
