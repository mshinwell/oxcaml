## What "validated" rests on, for a unit from OCaml

Beyond the trust ledger (the conversion to the model, the parser):

- the printing of `-drawfexpr`: the term validated is the one the
  parser reads back. It is the term the compiler simplifies only as far
  as printing and parsing lose nothing, and they do lose something: the
  kinds of the fields of a `Make_block` (read back as `any_value`) and
  the arities of calls (discrepancies V2-2, C2-5, R2-12). X5
  compared the term in the compiler's memory with the term read back
  for each unit: the subkind of the result of an application and
  the mark `[cold]` of a continuation handler are lost as well, and
  Simplify reads each (the README of the corpus has the places).
  With these the tool's Simplify knows less than the compiler's;
- the same printing where it says more than the compiler's term: a
  value that may be null is read as never null wherever the text
  writes its kind (discrepancy T4-13; found by T4). As far as this
  loss goes, the model's term before is the compiler's, as the
  conversion drops these kinds; the term after can differ where
  Simplify used the kind. The 13 units of the corpus that have such
  a kind are counted apart: the tool's verdict on each is
  "validated", and the row says that nothing in the tree shows that
  its term after is the compiler's, not that it is not;
- that the tool runs Simplify as the compiler would: the tool uses the
  default flags, and so does the command that makes the term. It does
  not where Simplify reads a mark of code that the printed term has
  not got: a functor, `[@cold]`, opaque code, the modes of
  parameters. One case is known: for code with no inlining
  attribute, the decision made at the declaration compares the size
  of a functor with the thresholds for functors, and a functor no
  larger than `small_functor_size` is to be inlined; the tool's
  Simplify, to which the functor is a function, compares it with the
  thresholds for functions and may leave the call (discrepancy V2-6;
  found by T4);
- what the conversion leaves out: depths, regions (the ledger has the
  entry).

- A known limit: the calls that the validator is told to leave are
  chosen by code and not by call. Every call of a piece of code of
  the list `kept` is left; a call of other code is inlined where it
  passes the checks of the inlining. Simplify can inline one call of
  a function and leave another, where the source says so
  (`[@inlined]` at one call and `[@inlined never]` at another;
  `[@unrolled 3]` on a call of a recursive function). Sources
  written by T4 to try it, which are not in this tree, are not
  validated. None of the units of the corpus or of the generator
  has it. Following it needs the calls to inline named one by one,
  which waits until a unit shows the shape without an attribute.
  One part does not wait: where the
  term after is left with code and a closure that nothing uses once
  the validation has inlined the call that Simplify left, they are
  to be removed from the term after by a rewrite that is an
  equivalence (the removal of unused static bindings is applied to
  the term before only, as a refinement).
- The term after could use what the unit binds its symbols to, as
  the term before does, by rewrites proved as equivalences of the
  unit run on its own: a load from a constant string, which Simplify
  does not evaluate (`string_get_checked.ml`), and a load from a
  block that Simplify has made a symbol (one generated unit with an
  exception) are in the term after only.

## Findings to keep in mind

- Nothing was found where the two runs differ, and nothing where the
  validator accepts a pair it should not.
- A unit that is undefined before Simplify in the model and defined in
  the compiler looks like a pass. The tool says "nothing to validate"
  of one that is not validated, and adds a line to one that is. Found
  so far: tupled functions called indirectly (now in the model); a handler
  that catches a predefined exception by name (V2-4); a comparison of
  an allocated value with itself; a load past the end of a string.
- A unit that declares an exception (`exception E`) calls a C function
  (`caml_fresh_oo_id`) and makes a block that is immutable and unique,
  at tag 248: it needs calls of C functions and the heap.
- `fst` and `snd` as the standard library declares them
  (`%field0_immut`, `%field1_immut`) are an immutable load with unknown
  tag and size, which the model has: `fst_snd.ml` is validated. Only
  `!` and a `%field0` written by hand are loads marked mutable.
- Simplify makes `x lxor (-1)` the unary `not`; it leaves `x - x` and
  `x lxor x` as they are.
- Where a handler ignores the exception, Simplify still passes it, and
  still allocates it (V2-5).
- The wrapper of a partial application is code marked `stub` in the
  term given to Simplify, with a direct call of the function through
  a value slot of its own closure. Simplify does not simplify a stub
  where its closure is made, and makes that call indirect
  (`partial_exported.ml`; found by T4).
- Simplify leaves some continuations that are applied once, the one
  whose handler binds the symbols of the unit among them.
- In the code of a function Simplify leaves a `Let` of a parameter of
  the code that nothing uses (`string_sum.ml`, three generated units).
