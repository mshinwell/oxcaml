# V2: the corpus, and units made from OCaml sources

What is under "Done" is merged: the wiring of the rewrites below into
the validator, and after it the names that a round is told not to
make. V2 also holds the files of the plan's V1 (the validator) for
now: `FlambdaNormalise*`, `FlambdaValidate*`, `FlambdaCompare*`.
Reviewer: R6.

## Done

- **A path from an OCaml source to the validator.**
  `middle_end/flambda2/tests/semantics/ocaml/from_ocaml.sh` makes of
  `X.ml` the term that `-drawfexpr` prints (`-nopervasives -nostdlib
  -stop-after middle_end`, with `X.mli` if there is one); the test tool
  reads it. The dune rules of that directory make each term again,
  compare it with the committed `X.fl`, run the tool and compare with
  `X.expected`. `README.md` there has the command, what each verdict
  means, what the conversion does to a unit, the lists of examples and
  what stops a unit from validating.
- **The corpus: 212 sources. 172 validated, 34 the same on one run and
  not validated, 2 undefined in the model before Simplify, 4 not
  checked.** The README has, for each unit that is not validated, what
  is missing, in one line, and the list of what used to stop a unit
  with the rewrite that removed it. Sources came from P1 (strings),
  V3 (functions and constants exported), V4 (loops), T4 (functions
  exported and used), T6 (values unboxed where branches meet) and C4
  (a mutable field).
- **A count over 600 generated units**
  (`tests/semantics/ocaml/census/`), with this series: 509 validated,
  91 not, none refused, no unit on which the two runs differ (the day
  before: 336, 256 and 8). With known inputs and results that are
  numbers, 150 of 150. Of the 91, 50 keep in the term after a
  continuation applied once, 37 wait for a better guess of what was
  lifted, 15 have a `Switch` that Simplify makes a tagging. The five
  units that have `poison` are run and compared; none is validated.
- **Normalisations**, each proved, with no axiom:
  - `load_known_blocks` (`FlambdaBlockLoadSpec.v`, refines);
  - `remove_unused_conts` (`FlambdaUnusedContsSpec.v`, equivalence);
  - `unbox_known_numbers` (`FlambdaUnboxSpec.v`, refines);
  - `share_known_primitives` (`FlambdaCseSpec.v`, refines; commutes
    with renaming): a pure primitive already computed is not computed
    again. `shareable` has the length of a string and the unary
    arithmetic on integers too;
  - `order_statics_as` (`FlambdaStaticsOrderSpec.v`, equivalence;
    commutes with renaming): the bindings of each static group of the
    term before in the order of the term after;
  - `rename_apart` (`FlambdaRenameApartSpec.v`, equivalence; commutes
    with renaming up to the names it makes, proved by N2): every
    binder of a term given a name of its own. The rounds use N2's
    `rename_apart_avoiding avoid`, which makes no name of the list
    given; `rename_apart` is its instance at the empty list;
  - `inline_sibling_calls` (`FlambdaInlineSiblingsSpec.v`, refines;
    commutes with renaming): in the body of code, the direct calls of
    the other code of its group are inlined;
  - `remove_unused_projections` (`FlambdaUnusedProjectionsSpec.v`,
    equivalence): an unused `Let` of the projection of a function slot
    from a closure that a `Let` around it made, at the kind `Value`.
    For the term after.
- **Calls that are not to be inlined.** `inline_calls`,
  `inline_known_calls`, the normalisations and `validate_unit` take a
  list of code ids, `kept`, whose calls are left alone. It is the
  caller's guess and is not trusted. The tool tries two lists in turn.
- **`validate_unit rounds unused slots Ls kept before after`**, with
  `order_statics_as after` around the term before in each comparison
  of normalised terms. The term before is normalised in V4's two
  phases; a round of the second is `normalise_before_inlined
  (rename_apart_avoiding avoid (inline_sibling_calls kept
  (inline_calls kept [] e)))`, with nothing to avoid where nothing is
  lifted and, after a lifting, the continuations of the units of the
  liftings (`unit_continuations`); after a lifting each round is
  followed by V3's use of the static closures in sight; in the
  comparison of the lifted term the term after has its code bound
  first (V3's `with_code_first`). Both theorems of soundness are
  proved.
- **`prim_may_fold`** says no of the primitives of the heap, so that
  no rewrite removes an allocation or a store when the machine runs
  them.
- **The conversion** (`tests/tools/flsemantics.ml`): drops depth
  variables; drops regions and converts a local allocation as one on
  the heap (decision D37, with comments for the human where it is
  done; discrepancy V2-3); converts the constant `poison`; refuses a
  unit with tupled code and a call that is not direct. The tool says
  so when it validates a unit whose term before is undefined in the
  model.

## Decided overnight (2026-11-11 and 12), for the human

1. **Regions** (D37, decided by the orchestrator for the human):
   dropped, local allocations converted as heap ones. Widened on
   2026-11-12 to the regions around a `try` (`Begin_try_region`,
   `End_try_region`), which every handler of the source has: dropped
   in the same way, the assumption being also that nothing allocated
   in a region that a raise left open is used once the handler has
   ended it. The ledger and the header of the tool say so. Cost of
   changing: every unit with a `try`, and `match_variant_local.ml`, is
   "not checked".
2. **Tupled functions.** Options: refuse all code marked tupled; refuse
   only a unit that also has a call that is not direct; model the mark.
   Chosen: the second, as a direct call gives the components and is
   run faithfully (agreed with C2). Cost of changing: two lines, and
   two examples become "not checked".
3. **Which calls the validator leaves alone.** The tool tries the code
   the term after still calls directly with the recursive code added,
   then the recursive code alone. Cost of changing: a few lines of the
   test tool; nothing proved depends on it.
4. **Which primitives `share_known_primitives` shares.** Those that
   compute a number from numbers or look at a value without reading
   memory that can change; not loads, not allocations. The compiler
   shares immutable allocations too (the file has a comment for the
   human on it). Cost of changing: the list `shareable`.
5. **A load marked mutable of a known block**: left as it is by
   `load_known_blocks`, as Simplify leaves it.
6. **Renaming binders apart, and the statements that the validator
   commutes with renaming** (N3's `FlambdaValidatorEquivarianceSpec.v`).
   `rename_apart` makes names, so a round commutes with a renaming
   only up to the names it makes. The orchestrator ruled: no statement
   is removed with its replacement owed. So the wiring of
   `rename_apart` lands with N3's statements for one round, for
   `normalise_before` and for the verdict (the validation answers the
   same on a pair and on the pair renamed, where the code of the term
   before is closed), and N2's statements that each rewrite of a round
   keeps scope.
7. **Trap actions are compared.** A rewrite that erases every trap
   action (`erase_traps`, proved an equivalence on the machine without
   a stack) made one more unit of fifteen validate and two fewer. The
   orchestrator ruled that it is not wired: the comparison of trap
   actions is the only thing the validation says of them. The units
   with exceptions wait for the rewrites that follow what Simplify does
   (V4's forwarding of applications, C5's demotion of handlers).
8. **Poison is converted** (the orchestrator, for D26): the model has
   the constant; a unit that has it is run and compared, and is
   "validated" or "not validated" like any other.
9. **Inlining between the code of one group is wired** (the
   orchestrator): it turns one unit of the corpus
   (`closure_argument_exported.ml`); the pattern is ordinary.
10. **The argument of a raise that nothing reads** (Simplify's
    `patch_unused_exn_bucket`): no rewrite for it. No unit shows it,
    and the flow analysis counts the first parameter of every
    exception handler as read (discrepancy V2-5).
11. **The verdict under renaming, with liftings made in turn** (N3's
    finding). `rename_apart` takes its names outside the names of the
    term it is given. After a first lifting and its normalisation the
    term may no longer mention the exception continuation of the unit,
    a binder made in a round could then have its number, and the check
    of well-formedness of a later lifting goes by that name. The
    wiring was merged with a second premise on N3's statement that the
    validation answers the same on renamed terms
    (`later_liftings_use_unit`), which the orchestrator allowed for
    that series. The premise is gone: the rounds after a lifting are
    told the continuations of the units of the liftings and make
    neither, and N3's statement has the one premise that the code of
    the term before is closed. `validate_unit` kept its arguments; the
    tool normalises its proposals of liftings with the same list. No
    verdict of the corpus changed, and what the tool prints of each of
    the 600 generated units is the same byte for byte. Whether the
    premise was needed is not established: no unit was found on which
    the collision happens, and with the numbering of the test tool it
    cannot (a name made is greater than every name of the term, and
    the tool numbers the continuations of the unit first). Soundness
    was not touched either way.

## What "validated" rests on, for a unit from OCaml

Beyond the trust ledger (the conversion to the model, the parser):

- the printing of `-drawfexpr`: the term validated is the one the
  parser reads back. It is the term the compiler simplifies only as far
  as printing and parsing lose nothing, and they do lose something: the
  kinds of the fields of a `Make_block` (read back as `any_value`) and
  the arities of calls (discrepancies V2-2, C2-5, R2-12);
- that the tool runs Simplify as the compiler would: the tool uses the
  default flags, and so does the command that makes the term;
- what the conversion leaves out: depths, regions (the ledger has the
  entry).

## Findings to keep in mind

- Nothing was found where the two runs differ, and nothing where the
  validator accepts a pair it should not.
- A unit that is undefined before Simplify in the model and defined in
  the compiler looks like a pass. The tool says "nothing to validate"
  of one that is not validated, and adds a line to one that is. Found
  so far: tupled functions called indirectly (now refused); a handler
  that catches a predefined exception by name (V2-4); a comparison of
  an allocated value with itself; a load past the end of a string.
- A unit that declares an exception (`exception E`) calls a C function
  (`caml_fresh_oo_id`) and makes a block that is immutable and unique,
  at tag 248: it needs calls of C functions and the heap.
- `fst` and `snd` as the standard library declares them
  (`%field0_immut`, `%field1_immut`) are an immutable load with unknown
  tag and size, which the model has: `fst_snd.ml` is validated. Only
  `!` and a `%field0` written by hand are loads marked mutable.
- Simplify makes `x lxor (-1)` the unary `not`; it leaves `x - x` and
  `x lxor x` as they are.
- Where a handler ignores the exception, Simplify still passes it, and
  still allocates it (V2-5).
- The wrapper that Simplify makes of a partial application calls the
  function through a value slot of its own closure, and leaves that
  call indirect (`partial_exported.ml`).
