# N1, names: status

Owner: N1. The document that says how names are treated is
`middle_end/flambda2/rocq/NAMES.md`. This file says what is done, what
is in progress and what was decided without the human.

## Done, in the series that makes the renaming enter code

- **The renaming enters code.** `rename_expr` renames code as the
  compiler does. The statements that rename a bound name, and the rules
  of `alpha_equivalent` that do, take the premise that code is closed;
  `rename_code_binders_statement` and the rule `Alpha_code` are new;
  `alpha_structural` is removed. The free names as functions and the
  three conditions are shown equivariant.
- **Renamings act on states and execution is equivariant**
  (`FlambdaEquivarianceSpec.v`): a step, a run and a behaviour commute
  with renaming, with no premise; `fold_constants` and `inline_calls`
  commute with it.
- **The terms are instances of the interface, and their binders name
  abstractions** (`FlambdaNominalInstancesSpec.v`).
- `NAMES.md`.

The semantics tests were run on that series: the extracted
`rename_expr` changes, and every example prints what its expected file
has.

## Done, in the series that carries this file

- **The three conditions on binders are conditions on the classes**
  (`FlambdaAlphaSpec.v`): alpha-equivalent terms have the same free
  names as functions, and their code is closed together, their binders
  distinct together and their names in scope together.
- **The comparison does not depend on the names**
  (`expr_eqb_equivariant_statement`): its answer on two terms and on
  the two terms renamed, with the names paired so far renamed too, is
  the same.
- **What the comparison accepts outside well-formed terms**: two pairs

  one that repeats a parameter
  (`expr_eqb_repeated_parameter_statement`) and one whose code is not
  closed (`expr_eqb_open_code_statement`). So neither condition of the
  converse can be dropped.

## Decided overnight

Each is a choice the human may reverse; the cost of doing so is given.

1. **The three checks are in `FlambdaBindersSpec.v`**, not in
   `FlambdaWellFormedSpec.v`. Options: in the file of well-formedness,
   as first agreed with the integrator, or below it. Chosen: below,
   because the invariant of a state is defined from `code_closed`, and
   the file of well-formedness is to state that invariant, so the
   checks have to be below both. The integrator agrees. Cost of
   changing: a cut and paste, and the invariant of a state moves to a
   later file.
2. **The comparison `expr_eqb` is the primary notion of "the same up
   to bound names"** (the human's default for the night), and
   `alpha_structural` is deleted. Options: keep `alpha_structural`
   beside it, repaired. Chosen: delete, since it was not reflexive and
   nothing used it. Cost of changing: about 150 lines to restore, with
   the rules for `Apply` and `Let_static` that it lacked.
3. **Every statement that renames a bound name takes the premise that
   code is closed**, and so does every rule of `alpha_equivalent` that
   renames. Options: (a) the premise; (b) restate the side conditions
   by the free names that go into code. Option (b) changes how the free
   names are presented and does not remove the restriction: where code
   is not closed, a binder of a continuation around it hides, by the
   syntax, a free continuation of the code that no call captures, and
   the comparison treats code as closed; so the statements would keep
   whatever restriction to closed code their soundness needs. Chosen:
   (a), which is true and costs nothing on well-formed terms. Cost of
   changing: it comes with the restating of the older accounts of free
   names, about thirty statements.
4. **`rename_variables_equivalent_statement` is kept**, with the
   premise, where the plan was to replace it by the equivariance of the
   machine. Both are now there. Cost of changing: delete one statement
   and its eight lines of proof.
5. **Expressions are an instance of the interface on the expressions
   whose code is closed** (`closed_expr`, a subset type). Options: (a)
   the subset; (b) all expressions, with those whose code is not closed
   identified with each other and given no free names; (c) no instance.
   Chosen: (a). The laws are false of expressions whose code is not
   closed (the header of `FlambdaNominalInstancesSpec.v` says why), and
   (b) would make the laws true by making them say nothing. The action
   on the subset tests that the renamed code is closed, because a
   definition in a `Spec` file cannot use a proof;
   `rename_closed_expr_term_statement` says the test never fails. Cost
   of changing: the instance and thirteen short proofs.
6. **The interface keeps its definition of equal abstractions by
   permutations.** The quantifier "for all but finitely many names" is
   a derived view, for one bound name and for a list of distinct bound
   names; for an abstract bindable there is no such form. Cost of
   changing: none is proposed.
7. **Step 3a went in before the epoch of kinds**, by the integrator's
   decision with mine, because the human asked for the nominal work
   first. The epoch of kinds is rebased over it; I help with that
   repair.
8. **The converse stays in the second prover's files**, where the plan
   was to fold its statement into `FlambdaCompareAlphaSpec.v`. Chosen
   because the statement needs the rules that compare two binders at a
   fresh name, which are that prover's. Cost of changing: move three
   statements.
9. **The statements added after the review of the series that makes
   the renaming enter code are a series of their own**, so that the
   reviewed series is merged as it was read.

## Agreements with other streams

- The integrator: adds the three conjuncts and the record for a unit's
  two continuations; stages the series that makes the renaming enter
  code, with the whole validation.
- Kinds: its series is rebased over this one; the files that change
  under it are `FlambdaNominal*`, `FlambdaAlpha*`, `FlambdaApplyProofs.v`
  and `FlambdaCompareAlphaProofs.v`.
- Types and aliases: their renamings are instances of the interface,
  written by their owners in their own files.
- Heap: locations are a sort of their own; `unused_let_statement` gains
  the premise that the defining expression has no effect when the heap
  lands, with the heap's predicate.
- Lifting, ranges, exceptions, the validator's passes: each states that
  its function commutes with renaming in the forms of `NAMES.md`,
  section 7. Where the function goes into code, the case of code
  becomes a recursive call with this series.
- The n-way join and meet: they take the names to avoid and use
  `fresh_name`; equivariance is stated with the permutation that
  relates two choices.

## Discrepancies with the compiler

N1-1 to N1-9. N1-3 and N1-4 are where the model is stricter than the
compiler (rows 5 and 6). N1-9 is new: the compiler's comparison of
terms has no case for a primitive of four arguments, so it judges a
term with one different from itself; the model's comparison is
reflexive on every term.
